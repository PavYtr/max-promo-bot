# Бот фестивальных розыгрышей MAX

Бот выдает промокоды партнеров и регистрирует пользователей в ежедневных розыгрышах после проверки подписки на канал партнера.

- На каждый день акции назначен один партнер. Повторный запрос промокода возвращает уже выданный код.
- Для участия в розыгрыше нужно подписаться на партнера и нажать «Проверить подписку». Закончились промокоды — участвовать все равно можно.
- Получение промокода или регистрация дают один шанс за день. Оба действия в один день также дают один шанс, максимум — 10.
- В разделе «Мои шансы» отображаются накопленные шансы, даты активности, партнеры, оставшиеся дни акции и главный приз: пять победителей по два билета.

## Запуск через Docker

Нужны Docker с Compose и токен бота MAX.

```sh
cp .env.example .env
```

В `.env` заполните `MAX_TOKEN` и выберите `BOT_MODE=polling` для запуска без публичного сервера. Если у бота уже подключен webhook, сначала удалите его подписку в MAX.

Укажите часовой пояс акции в `FESTIVAL_TIMEZONE`, инструкцию в `HOW_TO_TEXT` и правила в `RULES_TEXT`. Для приветственного баннера задайте `BANNER_URL` или `BANNER_TOKEN`. Для админ-команд нужны одновременно `ADMIN_IDS` и `ADMIN_CHAT_ID`.

```sh
make up                       # запустить бота, PostgreSQL и Redis
docker compose logs -f app     # посмотреть логи
curl http://localhost:8080/healthz
make down                     # остановить, сохранив данные
```

## Партнеры и промокоды

Подготовьте JSON по образцу [examples/partners.json](examples/partners.json): замените демонстрационные даты, партнеров, ссылки, призы и промокоды. Для проверки подписки назначьте бота администратором каналов партнеров.

```sh
docker compose cp examples/partners.json app:/tmp/partners.json
docker compose exec app /app/bot import /tmp/partners.json
```

Импорт добавляет новые даты. Повтор уже существующей даты отменяет импорт файла целиком. Небольшой JSON можно отправить в разрешенном админ-чате командой `/import {"partners":[...]}`.

Откройте бота в MAX и нажмите «Начать» или отправьте `/start`.

## Розыгрыши (MR3, пункты 1–6)

Команды доступны только пользователям из `ADMIN_IDS` в чате `ADMIN_CHAT_ID`:

- `/draw_daily [partner_id]` — дневной розыгрыш после закрытия регистрации. Без ID используется партнер текущего фестивального дня. Недоставленные подтверждения регистрации восстанавливаются; команду нужно повторить после доставки.
- `/draw_grand` — финальный розыгрыш после окончания последнего дня импортированного календаря в `FESTIVAL_TIMEZONE`. До запуска импортируйте полный календарь акции. Задайте согласованное число резервов в `GRAND_RESERVE_COUNT` (0–10000); пустое значение блокирует создание финала.

Дневной выбор равновероятный, финальный — с весом по числу накопленных шансов. Финал выбирает пять разных основных победителей по два билета и заданное число разных резервистов. Все шансы выбранного пользователя исключаются из дальнейшего выбора. При нехватке кандидатов розыгрыш целиком откладывается до решения по правилам акции.

Создание, состав участников, веса, исходный список победителей и призы сохраняются одной транзакцией. Повторные и одновременные команды возвращают ID сохраненного результата, без нового выбора. Исходный состав и распределение защищены от изменения в БД; резерв получает конкретный приз при активации в пункте 8 MR3. Пока результат имеет статус `pending_approval`, уведомления о выигрыше не отправляются. Утверждение и уведомления описаны ниже; получение приза и активация резервов относятся к пунктам 7–9 MR3.

Утвердить сохраненный результат: `/approve_draw draw_id` в разрешенном админ-чате. Статус `approved`, время/ID администратора и задания на уведомление всех основных победителей сохраняются одной транзакцией. Повторное и одновременное утверждение не создает дополнительные уведомления. Резервисты не уведомляются до активации.

Приложение запускает asynq-воркер очереди `winners` и диспетчер outbox. PostgreSQL хранит текст уведомления, срок ответа и состояние доставки; в Redis передается только ID выигрыша. Пока доставка не подтверждена в БД, диспетчер раз в минуту повторяет постановку задачи, включая восстановление после потери очереди Redis. Перед отправкой воркер проверяет утверждение и состояние победителя под блокировкой. После успешной отправки сохраняет `notified`, время доставки и дедлайн. Дневной срок берется из `response_seconds` партнера; перед утверждением финала задайте согласованный `GRAND_RESPONSE_SECONDS` (1–2147483647). Пустая настройка блокирует утверждение финала. Отсчет после успешной отправки должен быть закреплен в правилах акции.

Дневное уведомление содержит партнера, приз, количество и инструкцию; финальное — два билета и кнопку «Получить приз». Кнопки привязаны к ID выигрыша, их обработка и сбор данных реализуются в пункте 7 MR3. Постоянная ошибка MAX (например, недоступный получатель) сохраняет `unreachable` у победителя и `failed` у уведомления; временная ошибка оставляет доставку незавершенной. Для проверки: `SELECT winner_id,status,attempts,sent_at FROM winner_notifications;`. Автоматическая передача резерву и показ проблем администратору относятся к пунктам 8–9.

Отправка использует общий Redis-лимитер MAX. ID личного чата сохраняется при `bot_started` и `/start` в диалоге, чтобы уведомления и обычные ответы использовали один лимит чата. Если ID неизвестен, адресация и лимит используют ID пользователя. MAX не документирует ключ идемпотентности: после неоднозначного ответа API или сбоя между отправкой и фиксацией в БД возможно повторное сообщение. Повтор успешно зафиксированной задачи сообщение не отправляет и дедлайн не переносит.

Проверки: `make check`, `make integration` (нужны PostgreSQL и Redis из `make infra`). Интеграционные тесты применяют миграции в отдельных временных схемах и проверяют конкурентный запуск, откат, снимки данных, права команд и границы календаря.

## Запуск с webhook

В `.env` задайте `BOT_MODE=webhook`, случайный `WEBHOOK_SECRET` длиной 16–256 символов и `WEBHOOK_URL=https://ваш-домен/webhook`. Настройте HTTPS на порту 443 с перенаправлением запросов в приложение на порт 8080.

```sh
make up
docker compose exec app /app/bot subscribe
```

## Запуск без контейнера приложения

Нужен Go 1.26.1. Настройки берутся из переменных окружения; адреса PostgreSQL и Redis для этого режима уже указаны в [.env.example](.env.example).

```sh
set -a
. ./.env
set +a
make infra                    # запустить PostgreSQL и Redis
make migrate                  # подготовить базу данных
go run ./cmd/bot import examples/partners.json
make run                      # запустить бота
```
