# Бот фестивальных розыгрышей MAX

## Запуск

Нужны Docker с Compose и Go 1.26.1 для локальных команд.

```sh
cp .env.example .env
# Заполните MAX_TOKEN, WEBHOOK_SECRET; укажите баннер и утвержденные тексты.
make up
```

Compose запускает PostgreSQL 16, Redis 7 с AOF, одноразовую миграцию goose и приложение. Данные сохраняются в именованных томах. Локальные порты: приложение `127.0.0.1:8080`, PostgreSQL `127.0.0.1:15432`, Redis `127.0.0.1:16379`. В контейнерах используются внутренние адреса и порты. Пароль `festival` предназначен для локальной разработки.

`make up` требует токен. Для проверки запуска без аккаунта допустим `MAX_TOKEN=local-smoke-token make up`: откроется `/healthz`, но реальная отправка сообщений с таким токеном не работает. Webhook не регистрируется автоматически.

Для локальных Go-команд экспортируйте конфигурацию:

```sh
set -a
. ./.env
set +a
make infra
make migrate
make run
```

Для разработки выберите `BOT_MODE=polling`. До запуска удалите существующую webhook-подписку через `DELETE /subscriptions?url=...`: MAX запрещает одновременно использовать оба транспорта. Только один polling-процесс допускается блокировкой PostgreSQL. После перезапуска используется сохраненный marker; при первом запуске без marker MAX возвращает последнее событие, а не всю историю.

Для production задайте `BOT_MODE=webhook`, случайный `WEBHOOK_SECRET`, `WEBHOOK_URL=https://ваш-домен/webhook`. Настройте HTTPS reverse proxy с доверенным сертификатом на порту 443, перенаправляющий запросы в приложение. Проверив доступность сервера, зарегистрируйте подписку:

```sh
docker compose exec app /app/bot subscribe
```

Webhook проверяет `X-Max-Bot-Api-Secret`, ограничивает тело 1 МиБ и возвращает 200 только после сохранения события в БД. Недоступная БД дает 503 для повторной доставки MAX. `/healthz` проверяет PostgreSQL и Redis. Приложение корректно завершает HTTP-сервер и фоновые циклы по SIGTERM/SIGINT.

## Конфигурация

Все параметры приведены в [.env.example](.env.example).

| Переменная | Назначение |
| --- | --- |
| `MAX_TOKEN` | Токен MAX в заголовке Authorization; обязателен для serve/subscribe |
| `BOT_MODE` | `webhook` по умолчанию, `polling` только для разработки |
| `WEBHOOK_SECRET` | 16–256 символов; одинаковый для приложения и подписки |
| `WEBHOOK_URL` | Публичный HTTPS URL на порту 443 для команды subscribe |
| `MAX_API_URL` | `https://platform-api2.max.ru`; HTTP разрешен только локальному имитатору |
| `MAX_CA_FILE` | Дополнительный доверенный CA только для HTTP-клиента MAX; системные CA сохраняются |
| `HTTP_ADDR` | `:8080` |
| `DATABASE_URL`, `REDIS_URL` | Подключения; Compose подставляет внутренние адреса |
| `FESTIVAL_TIMEZONE` | IANA timezone, по умолчанию Europe/Moscow; требуется подтвердить календарь |
| `ADMIN_IDS`, `ADMIN_CHAT_ID` | Список MAX ID через запятую **и** разрешенный чат. Без обоих доступ закрыт |
| `BANNER_TOKEN` / `BANNER_URL` | Токен загруженного изображения или HTTPS URL; только один параметр |
| `HOW_TO_TEXT`, `RULES_TEXT` | Инструкция и правила; по умолчанию предварительные тексты |

Без предоставленного баннера меню работает с текстом и пятью кнопками; для полной проверки приветствия задайте один из `BANNER_*`. Загрузка изображения, доставка CSV, права проверки подписки и актуальные контракты описаны в [docs/MAX_API.md](docs/MAX_API.md).

## Импорт

В разрешенном админ-чате: `/admin` показывает справку; `/import {"partners":[...]}` импортирует JSON того же формата, что [examples/partners.json](examples/partners.json). Учитывайте лимит сообщения MAX 4000 символов. Большие файлы загружает оператор с доступом к окружению:

```sh
go run ./cmd/bot import examples/partners.json
```

В примере только вымышленные настройки. День и время закрытия проверяются в `FESTIVAL_TIMEZONE`; временные поля содержат RFC3339 с явным смещением. Один партнер на дату. Для каждого победного места обязателен приз с количеством единиц. Указываются число резервов, срок ответа в секундах, получатель персональных данных, инструкция получения и срок применения кода.

Импорт работает в одной транзакции, только добавляет новые дни, отклоняет неизвестные поля, некорректные даты, пустые обязательные поля, дубли дней, мест и кодов. Дубль уже существующей даты отменяет **весь** файл. Коды уникальны в пределах партнера. Обновление действующего партнера и дозагрузка кодов отдельной командой в MR 1 не предусмотрены.

## Проверки и команды

```sh
make build                 # bin/bot
make generate              # sqlc v1.29.0; результат хранится в internal/storage/db
make test                  # unit-тесты и HTTP-имитатор MAX
make test-race             # то же с детектором гонок
make vet
make infra
make integration           # отдельные временные схемы PostgreSQL и ключи Redis
make migrate               # goose up
make migrate-down          # откат последней миграции, удаляет ее данные
make down                  # остановить окружение, сохранить тома
```
